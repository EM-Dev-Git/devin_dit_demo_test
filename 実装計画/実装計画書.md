# トランスクリプト議事録作成API 実装計画書

## 1. プロジェクト概要

### 1.1 目的
音声トランスクリプトから自動的に議事録を生成するAPIシステムの構築

### 1.2 主要機能
- トランスクリプトファイルのアップロード
- OpenAI APIを使用した議事録自動生成
- JWT認証によるユーザー管理
- ログ機能による操作履歴管理

### 2.2 技術スタック
- **フレームワーク**: FastAPI
- **データベース**: PostgreSQL
- **認証**: JWT (PyJWT)
- **AI**: OpenAI API (GPT-4)
- **ログ**: Python logging + structlog
- **環境管理**: python-dotenv

## 3. 詳細設計

### 3.1 認証システム (JWT)

#### 3.1.1 データベーススキーマ
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    user_id VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 3.1.2 認証フロー
1. ユーザー登録 (`POST /auth/register`)
2. ログイン (`POST /auth/login`) → JWTトークン発行
3. 保護されたエンドポイントでのトークン検証

#### 3.1.3 実装ファイル
- `modules/auth.py`: JWT生成・検証ロジック
- `routers/auth.py`: 認証エンドポイント
- `schemas/user.py`: ユーザー関連のPydanticスキーマ

### 3.2 トランスクリプト処理

#### 3.2.1 処理フロー
1. トランスクリプトファイルアップロード (`POST /transcript/upload`)
2. ファイル形式検証（txt, json対応）
3. 内容の前処理・整形
4. データベースへの保存

#### 3.2.2 実装ファイル
- `modules/transcript_processor.py`: トランスクリプト処理ロジック
- `routers/transcript.py`: トランスクリプト関連エンドポイント
- `schemas/transcript.py`: トランスクリプト関連スキーマ

### 3.3 議事録生成 (OpenAI連携)

#### 3.3.1 OpenAI API設定
- モデル: GPT-4
- プロンプト設計: 議事録形式での要約生成
- レスポンス処理: 構造化された議事録データ

#### 3.3.2 生成フロー
1. 議事録生成リクエスト (`POST /minutes/generate`)
2. トランスクリプトデータ取得
3. OpenAI APIへのリクエスト送信
4. 生成された議事録の保存・返却

#### 3.3.3 実装ファイル
- `modules/openai_client.py`: OpenAI API連携
- `routers/minutes.py`: 議事録生成エンドポイント
- `schemas/minutes.py`: 議事録関連スキーマ

### 3.4 ログ機能

#### 3.4.1 ログ設計
- 構造化ログ（JSON形式）
- ログレベル: DEBUG, INFO, WARNING, ERROR
- ログ内容: API呼び出し、認証、エラー、処理時間

#### 3.4.2 実装
- `modules/logger.py`: ログ設定・ユーティリティ
- 各モジュールでのログ出力

### 3.5 環境設定

#### 3.5.1 環境変数 (.env)
```
# データベース
DATABASE_URL=postgresql://user:password@localhost:5432/dbname

# JWT設定
JWT_SECRET_KEY=your-secret-key
JWT_ALGORITHM=HS256
JWT_EXPIRE_MINUTES=30

# OpenAI API
OPENAI_API_KEY=your-openai-api-key
OPENAI_MODEL=gpt-4

# ログ設定
LOG_LEVEL=INFO
LOG_FILE_PATH=./logs/app.log

# アプリケーション設定
APP_HOST=0.0.0.0
APP_PORT=8000
DEBUG=False
```

## 4. API仕様

### 4.1 認証エンドポイント

#### POST /auth/register
```json
{
  "user_id": "string",
  "password": "string"
}
```

#### POST /auth/login
```json
{
  "user_id": "string",
  "password": "string"
}
```
レスポンス:
```json
{
  "access_token": "string",
  "token_type": "bearer"
}
```

### 4.2 トランスクリプトエンドポイント

#### POST /transcript/upload
- ヘッダー: `Authorization: Bearer <token>`
- ボディ: multipart/form-data (ファイル)

### 4.3 議事録エンドポイント

#### POST /minutes/generate
```json
{
  "transcript_id": "integer"
}
```
レスポンス:
```json
{
  "minutes_id": "integer",
  "content": "string",
  "created_at": "datetime"
}
```

## 5. データベース設計

### 5.1 テーブル構成

#### users テーブル
- id (SERIAL PRIMARY KEY)
- user_id (VARCHAR UNIQUE)
- password_hash (VARCHAR)
- created_at, updated_at (TIMESTAMP)

#### transcripts テーブル
- id (SERIAL PRIMARY KEY)
- user_id (INTEGER FOREIGN KEY)
- filename (VARCHAR)
- content (TEXT)
- created_at (TIMESTAMP)

#### minutes テーブル
- id (SERIAL PRIMARY KEY)
- transcript_id (INTEGER FOREIGN KEY)
- user_id (INTEGER FOREIGN KEY)
- content (TEXT)
- created_at (TIMESTAMP)
